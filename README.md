# Каталог репетиторів

Навчальний проєкт для лабораторної роботи №7 «Аудит продуктивності».
Це SPA-каталог репетиторів: пошук, фільтри, сортування, обрані, картка з деталями.
Дані (≈2000 репетиторів) генеруються локально й детерміновано — у всіх однакові,
інтернет не потрібен.

## Вимоги

- Node.js 18+ (перевірено на Node 22)
- Google Chrome (для DevTools, React Profiler і Lighthouse)
- Розширення React Developer Tools

## Запуск

```bash
npm install
npm run dev        # режим розробки, http://localhost:5173
```

Для замірів використовуйте **production-збірку** — у dev-режимі React працює
повільніше і цифри будуть спотворені:

```bash
npm run build
npm run preview    # http://localhost:4173
```

> React Profiler у production-збірці за замовчуванням не працює. Для профілювання
> компонентів користуйтеся dev-режимом, а підсумкові цифри (DevTools, Lighthouse)
> знімайте на `preview`.

## Тести

```bash
npm test           # одноразовий запуск
npm run test:watch # режим спостереження
```

Тести — Vitest + Testing Library + jsdom. Приклад: `src/__tests__/SearchBar.test.jsx`.
Свій regression-тест додавайте поруч, у `src/__tests__/`.

## Структура

```
src/
  App.jsx               кореневий компонент, стан каталогу
  components/           UI-компоненти
  hooks/                власні хуки
  utils/                пошук, сортування, форматування
  api/                  довідникові дані
  data/                 генератор даних репетиторів
  styles/               стилі
public/
  photos/, images/      фото репетиторів і банер
```

## Аудит продуктивності

Звіт лежить у [REPORT.md](REPORT.md), а скріншоти, трейси й результати замірів у папці [report/](report/).

Заміри я робила скриптом, щоб їх можна було повторити. Спочатку збірка і preview в окремому терміналі:

```bash
npm run build
npm run preview
```

Потім у другому терміналі:

```bash
npm run perf -- назва
npm run perf -- назва --only type,scroll --runs 3 --trace=scroll
npm run perf:profile
```

Перша команда проганяє всі сценарії по 5 разів і зберігає медіани в `report/data/назва.json`.
Друга запускає тільки вибрані сценарії по 3 рази і ще записує трейс прокрутки (`--trace` без
назви записує трейси всіх сценаріїв). Третя показує, скільки часу забирає кожна функція
(те саме, що вкладка Bottom-Up в DevTools).

Щоб порівняти дві версії, стару збірку можна запустити на іншому порту і передати її адресу
через `--before`. Тоді скрипт міряє обидві версії по черзі, запуск старої, запуск нової і так далі:

```bash
npm run perf -- назва --before http://localhost:4175/
```

Скрипт запускає встановлений Google Chrome. Якщо він стоїть не в стандартному місці, шлях можна
вказати в змінній `CHROME_PATH`. Трейси з `report/traces/` можна відкрити в DevTools на вкладці
Performance через кнопку "Load profile".
